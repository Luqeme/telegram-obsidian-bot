## 0. Что изменено относительно v1.0

ТЗ v1.0 было рабочим, но содержало 1 блокер и 9 внутренних противоречий. Ниже — журнал решений. Каждое изменение обосновано; если пункт не указан в таблице, он остался как в v1.0.

| № | Было (v1.0) | Стало (v2.0) | Почему |
|---|---|---|---|
| 1 | LLM `llama-3.3-70b-versatile` | **`openai/gpt-oss-120b`** | Модель отключена на Groq 16.08.2026 для free/dev тарифа. Запросы вернут `model_decommissioned`. |
| 2 | LLM возвращает готовый Markdown с frontmatter | LLM возвращает **строгий JSON**, Markdown собирает код | Модель не знает текущее время (врёт в `created`), путает `type`/`source`/`status`, пересказывает «оригинал», ломает файл лишними ```. См. §7. |
| 3 | `category`: 3 разных списка в разных разделах | Единый enum: `Идея, Задача, Мысль, Контент, Встреча` | Устраняет противоречие §4 / §5 / шаблона. |
| 4 | `status: unread` и `status: inbox` | **`status: inbox`** | Логика инбокса; `unread` не используется далее в системе. |
| 5 | `category: [Идея \| Задача \| ...]` | `category: Задача` (строка) | В YAML это была бы невалидная/бессмысленная конструкция. |
| 6 | Два разных текста подтверждения | Одна карточка + путь + ссылка на файл в GitHub | Покрывает оба критерия приёмки одновременно. |
| 7 | Аудио через `tempfile` + `finally` | **В память (`BytesIO`)**, без записи на диск | Устраняет целый класс ошибок. «Гарантированное удаление» выполняется строже — удалять нечего. |
| 8 | `PyGithub` или REST | **`httpx` (async)** | `PyGithub` синхронный, блокирует event loop, требует `asyncio.to_thread`. Один `PUT` проще. |
| 9 | Нет тестов | Минимальный набор pytest | Frontmatter — самое хрупкое место, ломается молча. |
| 10 | Нет таймзоны | `TIMEZONE` в `.env` | `created` и имя файла иначе зависят от сервера. |
| 11 | Нет защиты от 429 / таймаутов | Retry с backoff + явные таймауты | Groq free tier отдаёт 429 регулярно; без этого бот «умирает» на глазах. |
| 12 | Нет обработки пустого/мусорного ввода | Порог длины + флаг `is_meaningful` от LLM | На «ок» LLM выдаёт бред, и в vault появляется мусорный файл. |

## 1. Цель и ключевой сценарий

Асинхронный Telegram-бот, который принимает **голосовые и текстовые** заметки, транскрибирует аудио, структурирует содержимое через LLM и коммитит готовую Markdown-заметку в GitHub-репозиторий хранилища Obsidian.

**Сценарий:** пользователь на бегу наговаривает мысль боту → через ~5–10 секунд получает карточку «сохранено, вот файл, вот теги» → заметка уже лежит в `00_Inbox/` и подхватывается Obsidian Sync на всех устройствах.

**Главный принцип:** бот не должен терять заметки и не должен падать. Любой сбой API — это сообщение пользователю и запись в лог, а не stack trace в консоли.

## 2. Стек и модели

### 2.1 Базовый стек

| Слой | Выбор | Версия |
|---|---|---|
| Язык | Python | 3.10+ |
| Telegram | `aiogram` | 3.x (>=3.20) |
| HTTP | `httpx` (AsyncClient) | >=0.27 |
| Конфиг | `pydantic-settings` | >=2.4 |
| Валидация | `pydantic` | >=2.x |
| Тесты | `pytest`, `pytest-asyncio` | — |

`ffmpeg` **не нужен**: Telegram отдаёт голосовые как `.ogg`/Opus, Groq принимает этот формат нативно.
`PyGithub` **не нужен**: GitHub вызывается одним REST-запросом.

### 2.2 Модели Groq (актуально на 03.11.2026)

| Задача | Модель | Цена | Обоснование |
|---|---|---|---|
| Speech-to-Text | **`whisper-large-v3`** | $0.111 / час | Production-модель, WER 10.3% — лучшая точность для русского. `turbo` (12%, $0.04) доступен как дешёвая альтернатива через `.env`. |
| LLM | **`openai/gpt-oss-120b`** | $0.15 / $0.60 за 1M | Production-модель, 131K контекст, ~500 t/s, **поддерживает Structured Outputs** (`json_schema`). Официальная замена Llama 3.3 70B. |

**Почему не `qwen/qwen3.8-27b`:** это Preview-модель (может исчезнуть без предупреждения), стоит в 5 раз дороже на output ($4.00 vs $0.60 за 1M) и не даёт выигрыша на задаче «сделай из текста JSON на 200 токенов».

**Обе модели задаются через `.env`**, чтобы следующая депрекация не требовала правки кода.

> ⚠️ Контроль: раз в квартал проверять `https://console.groq.com/docs/deprecations`. При старте бот опционально пингует `GET /openai/v1/models` и пишет в лог warning, если настроенной модели нет в списке.

## 3. Архитектура

```
Telegram
   │  voice / text
   ▼
┌──────────────────────┐
│ Auth Middleware      │  user_id ∈ ALLOWED_TELEGRAM_USERS ?
└──────────┬───────────┘  нет → «⛔ Доступ ограничен» → stop
           ▼
┌──────────────────────┐
│ handlers/notes.py    │  chat_action: record_voice / typing
└──────────┬───────────┘
           │ bytes (ogg) ──────────────► Groq /audio/transcriptions
           │                              whisper-large-v3, language=ru
           ▼
┌──────────────────────┐
│ services/groq_service│  текст
│  .structure_note()   │──────────────► Groq /chat/completions
└──────────┬───────────┘                gpt-oss-120b, json_schema
           │ NoteDraft (pydantic)
           ▼
┌──────────────────────┐
│ services/note_builder│  JSON → YAML frontmatter + Markdown
│  .build_markdown()   │  + slug + имя файла
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ services/github_svc  │  PUT /repos/{owner}/{repo}/contents/{path}
└──────────┬───────────┘
           ▼
     карточка пользователю
```

Все внешние вызовы — `async`, один общий `httpx.AsyncClient` на процесс (создаётся в lifespan, закрывается при остановке).

## 5. Конфигурация

### 5.1 `.env.example`

```ini
# ── Telegram ─────────────────────────────────────────────
TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
# через запятую, без пробелов (пробелы парсер срежет)
ALLOWED_TELEGRAM_USERS=123456789,987654321

# ── Groq ─────────────────────────────────────────────────
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
GROQ_STT_MODEL=whisper-large-v3
GROQ_LLM_MODEL=openai/gpt-oss-120b

# ── GitHub ───────────────────────────────────────────────
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
GITHUB_REPO=username/my-obsidian-vault
GITHUB_BRANCH=main
OBSIDIAN_INBOX_DIR=00_Inbox

# ── Прочее ───────────────────────────────────────────────
TIMEZONE=Asia/Yekaterinburg
LOG_LEVEL=INFO
MAX_AUDIO_MB=20
# true — латиница в именах файлов, false — кириллица
FILENAME_TRANSLITERATE=false
```

### 5.2 Правила валидации (`config.py`)

- `ALLOWED_TELEGRAM_USERS` → `list[int]`, парсинг строки с запятыми, пустые элементы отбрасываются. Пустой список = **ошибка старта** (иначе бот открыт всем).
- `GITHUB_REPO` → строго `owner/repo` (ровно один `/`, обе части непустые).
- `OBSIDIAN_INBOX_DIR` → обрезать ведущие/хвостовые `/`; допускается вложенность (`10_Notes/Inbox`).
- `TIMEZONE` → `ZoneInfo`, при неизвестной зоне — ошибка старта с понятным текстом.
- Отсутствие любой обязательной переменной → **падение на старте** с человекочитаемым сообщением, а не `KeyError` в рантайме.

`.env` в git не попадает никогда. В README — предупреждение про `GITHUB_TOKEN`.

## 6. User Flow

### 6.1 Проверка доступа (до любой обработки)

`AllowedUsersMiddleware` на событиях `message`.
- `event.from_user.id` в списке → пропустить.
- Нет в списке → ответить `⛔ Доступ ограничен.` **один раз**, записать в лог `WARNING` с `user_id`, вернуть `None` (остановить цепочку).
- Сообщения без `from_user` (анонимные админы каналов) — отбрасывать.

### 6.2 Голосовое сообщение

1. `send_chat_action(chat_id, "record_voice")`.
2. Проверить `voice.file_size` и `voice.duration`:
   - файл > `MAX_AUDIO_MB` → «⚠️ Запись слишком большая (N МБ, максимум 20)». Выход.
   - длительность > 20 минут → отказ (лимит Whisper-сегмента и здравого смысла).
3. `bot.download(file_id)` → `io.BytesIO` (в памяти, на диск не пишем).
4. `groq_service.transcribe_audio(buf, filename="voice.ogg")`:
   - `POST /openai/v1/audio/transcriptions`, multipart: `file`, `model`, `language=ru`, `response_format=json`, `temperature=0`.
   - Таймаут 120 с.
5. Если расшифровка пустая/короче 10 символов → «🤔 Не удалось разобрать речь, попробуй ещё раз». Выход.
6. Перейти к §6.4.

### 6.3 Текстовое сообщение

1. Текст короче 15 символов или без букв → «🤔 Слишком коротко, чтобы сделать заметку». Выход.
2. `send_chat_action(chat_id, "typing")`.
3. Перейти к §6.4.

### 6.4 Структурирование и сохранение

1. `groq_service.structure_note(text, source="voice"|"text")` → `NoteDraft` (§7).
2. `draft.is_meaningful == False` → «🤔 В сообщении нет содержания для заметки». Выход (файл не создаётся).
3. `note_builder.build_markdown(draft, original_text, source)` → строка Markdown (§8).
4. `note_builder.make_filename(draft.title, now)` → `2026-11-03_14-30-05_refaktoring-avtorizacii.md`.
5. `github_service.push_markdown_note(path, content, commit_message)` → `html_url`.
6. Отправить карточку (§10).

**Порядок важен:** статус «печатает» держится на время шагов 1–5, чтобы пользователь видел активность.

## 7. Контракт с LLM: JSON вместо Markdown

### 7.1 Pydantic-модель

```python
class NoteDraft(BaseModel):
    is_meaningful: bool          # False, если в тексте нет содержания для заметки
    title: str                   # 3–7 слов, без эмодзи и кавычек
    category: Literal["Идея", "Задача", "Мысль", "Контент", "Встреча"]
    tags: list[str]              # 2–4, русский kebab-case или латинский термин
    summary: str                 # 2–3 предложения
    tasks: list[str]             # [] если задач нет
```

### 7.2 Вызов Groq

```python
POST https://api.groq.com/openai/v1/chat/completions
{
  "model": settings.groq_llm_model,          # openai/gpt-oss-120b
  "messages": [
    {"role": "system", "content": SYSTEM_PROMPT},
    {"role": "user",   "content": text}
  ],
  "temperature": 0.3,
  "max_completion_tokens": 1200,
  "response_format": {
    "type": "json_schema",
    "json_schema": {"name": "note_draft", "strict": True, "schema": NOTE_DRAFT_SCHEMA}
  }
}
```

`NOTE_DRAFT_SCHEMA` — JSON Schema с `"additionalProperties": false` и `required` для всех полей.

**Fallback:** если провайдер вернёт ошибку на `json_schema`, повторить один раз с `{"type": "json_object"}` и **тем же** промптом, затем провалидировать через `NoteDraft.model_validate_json`. Если и это не удалось — ошибка пользователю, файл не создаём.

### 7.3 Почему так, а не «LLM пишет Markdown»

| Проблема при генерации Markdown моделью | Как решается в v2 |
|---|---|
| `created` выдуман (модель не знает время) | Дата ставится кодом в момент обработки |
| Кривой/неполный YAML → Dataview не видит поля | Frontmatter собирается кодом по шаблону, покрыт тестом |
| Модель пересказывает «оригинал» вместо дословной расшифровки | Оригинал вставляет код **как есть** (требование «дословно») |
| Обёртки ```markdown, «Конечно, вот заметка» | Структурно невозможно: ответ — JSON |
| Нельзя программно показать теги в карточке | `tags` — это список, а не строка внутри Markdown |

## 8. Сборка заметки

### 8.1 Frontmatter

Собирается **вручную** (не `yaml.dump`), чтобы контролировать порядок ключей и формат даты. Тест обязан проверять результат через `yaml.safe_load`.

```yaml
---
created: 2026-11-03T14:30:00
title: "Рефакторинг авторизации на JWT"
type: inbox-voice
category: Задача
tags:
  - backend
  - пет-проект
status: inbox
source: telegram
---
```

Правила:
- `created` — локальное время в `TIMEZONE`, формат **ISO 8601** `YYYY-MM-DDTHH:MM:SS`, без кавычек. Именно этот формат Dataview парсит как дату; вариант с пробелом остаётся строкой и ломает запросы.
- `title` — человекочитаемый заголовок (из LLM). Нужен, чтобы дашборд показывал его вместо имени файла с датой.
- `type` — `inbox-voice` | `inbox-text` (ставит код по типу входящего сообщения).
- `category` — одно значение из enum, строка.
- `tags` — YAML-список, 2–4 элемента. Значения санитизируются: нижний регистр, пробелы → `-`, вырезаются `#`, `:`, `[`, `]`, `,`, кавычки. Дубликаты убираются.
- `status` — всегда `inbox`.
- `source` — всегда `telegram`.
- Если поле из LLM пустое и заменить нечем — ключ **не выводится** (лучше отсутствие, чем `tags: []`).

### 8.2 Полный шаблон файла

```markdown
---
created: 2026-11-03T14:30:00
title: "Рефакторинг авторизации на JWT"
type: inbox-voice
category: Задача
tags:
  - backend
  - пет-проект
status: inbox
source: telegram
---

# Рефакторинг авторизации на JWT

## 💡 Суть
Нужно отказаться от сессий в пользу JWT с access/refresh токенами. Отдельно зафиксирована бытовая задача по оплате интернета.

## 📋 Задачи
- [ ] Изучить PyJWT
- [ ] Оплатить интернет в четверг

---
> 🎙 **Оригинал:**
> Слушай, надо не забыть в четверг оплатить интернет, а ещё я подумал, что можно в пет-проекте переписать авторизацию на JWT.
```

Правила:
- Блок `## 📋 Задачи` **не выводится вовсе**, если `tasks == []`. Строка «Задач не обнаружено» не пишется — она засоряет базу.
- `## 💡 Суть` выводится всегда, если `summary` непустой (пустой заголовок хуже отсутствующего).
- Иконка у оригинала зависит от источника: `🎙` для голоса, `📝` для текста.
- Оригинал — дословно, как пришёл (после транскрипции), с заменой переводов строк на `> ` для корректной цитаты. Markdown-спецсимволы в цитате не экранируются (Obsidian справляется), но строки, начинающиеся с `#` или `>`, префиксуются, чтобы не ломать структуру.
- Файл всегда заканчивается одним `\n`.

### 8.3 Имя файла

```
{YYYY-MM-DD}_{HH-mm-ss}_{slug}.md
```

- Время — из `TIMEZONE`, момент обработки.
- `slug` — заголовок, приведённый к безопасному виду. Режим задаётся `FILENAME_TRANSLITERATE`:
  - `true` — транслитерация в латиницу (`а-я` → `a-z`, `ё→e`, `й→y`, `ъ/ь` → пропуск);
  - `false` — кириллица сохраняется (`оплатить-интернет`).
  В обоих режимах: пробелы и пунктуация → `-`, недопустимые символы отбрасываются.
- Обрезка до **40** символов по границе слова, схлопывание повторных `-`, обрезка `-` по краям.
- Пустой результат → `note`.
- Коллизия (файл уже есть: GitHub вернул `422 "sha" wasn't supplied`): добавить `-2`, `-3`, … до 5 попыток.

Транслитерация — собственный словарь в `note_builder.py`, без внешних зависимостей.

## 9. Системный промпт (`prompts.py`)

```text
Ты — персональный секретарь и архитектор базы знаний по методологии Zettelkasten и GTD.
На вход приходит сырая мысль или расшифровка голосового сообщения. Твоя задача — разобрать её
и вернуть структурированные данные. Отвечай ТОЛЬКО валидным JSON по заданной схеме.

Правила:
1. is_meaningful — false, если текст не содержит осмысленного содержания (приветствие, случайный
   набор слов, обрывок без смысла). В этом случае остальные поля заполни минимально корректно.
2. title — главная тема, 3–7 слов, без эмодзи, без точки в конце, без кавычек. Не повторяй
   вводные слова («Надо», «Слушай»). Пиши по-русски.
3. category — ровно одно значение:
   - «Задача» — есть конкретное действие, поручение или дедлайн;
   - «Идея» — гипотеза, замысел, предложение что-то сделать;
   - «Мысль» — рассуждение, наблюдение, вывод;
   - «Контент» — материал для статьи, видео, поста;
   - «Встреча» — итоги разговора, созвона, план встречи.
4. tags — 2–4 тега. Русские слова в kebab-case (например: пет-проект, здоровье, финансы).
   Устоявшиеся технические термины можно латиницей (backend, jwt, ai). Без знака #.
   Теги должны помогать найти заметку через полгода, а не пересказывать заголовок.
5. summary — суть в 2–3 предложениях, нейтрально, без «автор говорит» и без воды.
6. tasks — только реальные призывы к действию, поручения и дедлайны, которые явно прозвучали.
   Формулируй как действие: «Оплатить интернет в четверг», «Изучить PyJWT».
   НЕ придумывай задачи. Если задач нет — верни пустой массив.
7. Не добавляй ничего от себя: ни идей, ни задач, ни выводов, которых не было в тексте.
```

Промпт не содержит текущую дату — она не нужна модели, `created` ставит код.

## 10. Синхронизация с GitHub

### 10.1 Запрос

```python
PUT https://api.github.com/repos/{owner}/{repo}/contents/{path}
Authorization: Bearer {token}
Accept: application/vnd.github+json
X-GitHub-Api-Version: 2022-11-28

{
  "message": "Add note from Telegram: {title}",
  "content": base64(content.encode("utf-8")),
  "branch": "main"
}
```

- `path` URL-энкодится по сегментам (пробелы, кириллица в имени папки).
- Таймаут: `connect=10`, `read=20`.
- Успех — `201 Created`. Из ответа берётся `content.html_url` (ссылка на файл).

### 10.2 Ошибки

| Код | Сообщение пользователю | Действие |
|---|---|---|
| `401` | `❌ GitHub: токен недействителен или истёк.` | лог `ERROR`, без ретраев |
| `403` / `404` | `❌ GitHub: нет доступа к репозиторию {repo}.` | лог `ERROR`, без ретраев |
| `422` (sha) | — | файл существует → новое имя (`-2`), ретрай |
| `429` / `5xx` | `❌ GitHub временно недоступен, попробуй ещё раз.` | 3 попытки, backoff 1s → 2s → 4s |

Токен: classic — scope `repo`; fine-grained — **Contents: Read & Write** на конкретный репозиторий. В логах токен никогда не выводится (только `***`).

## 11. Ответ пользователю

Единый формат, `parse_mode="HTML"`, все подставляемые значения экранируются через `html.escape`.

```html
✅ <b>Заметка сохранена в Obsidian</b>

📁 <code>00_Inbox/2026-11-03_14-30-05_refaktoring-avtorizacii.md</code>

🏷 <code>#backend</code> <code>#пет-проект</code>

💡 <b>Суть</b>
Нужно отказаться от сессий в пользу JWT с access/refresh токенами…

📋 <b>Задачи</b>
• Изучить PyJWT
• Оплатить интернет в четверг
```

- Общая длина — не более 4000 символов; `summary` при необходимости обрезается по границе предложения.
- Теги выводятся как `#тег` (удобно копировать в Obsidian).

**Сообщения об ошибках** (всегда, без stack trace):
- `❌ Не удалось расшифровать аудио. Попробуй ещё раз или отправь текстом.`
- `❌ Не удалось структурировать заметку. Попробуй переформулировать.`
- `❌ Ошибка при сохранении в GitHub: {причина}. Заметка не потеряна — текст ниже:\n{исходный текст}`

Последний пункт важен: если GitHub упал, пользователь получает свой текст обратно и может переслать позже.

## 12. Безопасность

1. **Whitelist middleware** — единственная точка авторизации, навешивается на все `message`-хендлеры. Не «проверка внутри хендлера».
2. Неавторизованному — отказ, обработка не выполняется, файлы не создаются.
3. `.env` в `.gitignore`; в репозиторий попадает только `.env.example` с заглушками.
4. В логи не пишутся: `TELEGRAM_BOT_TOKEN`, `GROQ_API_KEY`, `GITHUB_TOKEN`, полный текст заметок (только `chat_id`, `user_id`, длина, статус).
5. Текст пользователя попадает в LLM и в файл — это ожидаемо и указано в README.
6. Репозиторий рекомендуется **приватный**.

## 13. Обработка ошибок, ретраи, устойчивость

| Ситуация | Поведение |
|---|---|
| Groq 429 / 5xx | 3 попытки, backoff 1s → 2s → 4s + jitter, затем ошибка пользователю |
| Groq таймаут (>120 с) | ошибка «не удалось расшифровать», лог с длительностью |
| Невалидный JSON от LLM | 1 ретрай (fallback на `json_object`), затем ошибка |
| GitHub 429 / 5xx | 3 попытки, backoff, затем ошибка + возврат текста |
| Ошибка валидации `.env` | падение на старте с понятным сообщением |
| Исключение внутри хендлера | глобальный `@dp.errors()`, лог `exception`, пользователю «внутренняя ошибка» |
| Двойная отправка (повтор update) | не критично: имя файла с секундами, дубль максимум один |

**Гарантии:**
- Бот не завершает процесс ни при одной ошибке API.
- Временных файлов не существует — аудио живёт только в `BytesIO`.
- Если сохранение не удалось, исходный текст возвращается пользователю.

## 14. Логирование

- `logging` в stdout, формат: `%(asctime)s | %(levelname)-8s | %(name)s | %(message)s`.
- Уровень из `LOG_LEVEL`.
- Обязательные события:
  - `INFO` старт/остановка, модель, репозиторий, число разрешённых пользователей;
  - `INFO` `note_saved user_id=… source=voice chars=… path=…`;
  - `WARNING` отказ в доступе;
  - `ERROR` ошибки внешних API с кодом и кратким телом ответа (без токенов);
  - `DEBUG` тайминги этапов (transcribe / llm / github).

## 16. Критерии приёмки

- [ ] 1. Голосовое сообщение → в чат приходит карточка с путём `00_Inbox/YYYY-MM-DD_...md` и ссылкой.
- [ ] 2. Текстовое сообщение → то же самое, `type: inbox-text`.
- [ ] 3. В GitHub (ветка `main`) появляется коммит `Add note from Telegram: …`.
- [ ] 4. Frontmatter парсится `yaml.safe_load`; Obsidian Properties и Dataview корректно видят `created`, `category`, `tags`, `status`.
- [ ] 5. `created` совпадает с реальным локальным временем (±1 мин), а не с фантазией модели.
- [ ] 6. Блок «Оригинал» содержит дословную расшифровку.
- [ ] 7. Пользователь вне whitelist получает «Доступ ограничен»; файл не создаётся.
- [ ] 8. При недоступном Groq бот отвечает ошибкой и продолжает работать (следующее сообщение обрабатывается).
- [ ] 9. При недоступном GitHub бот отвечает ошибкой **и возвращает исходный текст**.
- [ ] 10. Запуск одной командой `python bot.py`; неверный `.env` → понятная ошибка до начала polling.
- [ ] 11. `pytest -q` зелёный.
- [ ] 12. На диске не остаётся аудиофайлов ни при успехе, ни при исключении.
- [ ] 13. Смена модели выполняется только правкой `.env`.

## 18. Вне рамок v1

Осознанно не делаем, чтобы не раздувать:
- OCR фотографий и распознавание PDF/документов;

- напоминания и повторяющиеся задачи;

- дедупликация одинаковых заметок.
